# 人物造型定稿与提示词一致性审核

人物资产提示词在读取各库后、交付或提交生图前必须执行本规范。参考库提供可选结构，不能随机抽取词条拼装。审美目标为国内3D半写实国漫漫剧的角色吸引力：面部有记忆点、身份与气质可读、全身比例协调、材质精致、适合连续镜头。用户认可的造型与纠正优先；这些是本项目设计目标，不冒充红果或其他平台的官方审美标准。

## 1. 先定整套方案

任何题材的人物资产提示词都必须先写【风格类型/画面风格】行，按题材分派并全剧统一：**玄幻/修仙/古风题材默认 3D半写实国漫CG**；**都市/现代题材默认 高精度3D半写实BJD人偶**（用户 2026-10 拍板，定义见 `character-prompt-style-variants.md` §2 该行）；项目视觉圣经或用户指令可覆盖，覆盖后全剧一致。同时在【避免】里配套写出该风格的负向类型锁（通用：真人写实照片、手绘2D、Q版三头身、塑料假脸；BJD 另加：真实毛孔油光、过度写实皱纹、成人皮肤纹理、幼态大眼娃娃脸）。UE5、PBR、8K 只是渲染与质感维度，只能写在本行修饰位或【妆面】【环境与光线】，**不得取代或省略类型声明**。缺类型行、把质感词当成类型、类型行与视觉圣经不一致、或同剧混用两种类型行，均判定未完成。**类型行与肤质描述必须自洽**：写 BJD 类型行时不得同时写"保留毛孔/细腻绒毛/真实皮肤纹理"；写国漫类型行时不得写"人偶般无瑕假面"。

**资产板画面规格（全题材通用硬项，依据 `visual-assets.md` 四视图版式）**：①背景必须是**单一纯色无缝底——白底或淡灰底**，不得出现环境场景、家具、道具、地面投影、渐变或第二背景色；宴会厅、住宅、街景等环境只用于剧情镜头，不得写进资产板提示词；②画面内**不得出现任何文字**（角色名、标签、色卡、编号、尺寸标注、说明、logo、水印、乱码标签），也不得出现边框、标尺、分割线、额外头像窗或细节小窗；③提示词正文只写画面内容，不得把"项目/批次/文件名/配对对象/状态"等元信息当作画面描述写入。缺背景纯色要求、出现文字或场景背景、把元信息混入画面，均判定未完成。

默认角色层级为男主/女主。只有用户明确指定配角、NPC、路人、侍从等词时，才允许按配角规则降低轮廓独特度、装饰密度、色彩对比或焦点数量；降级后仍须完整、好看且有身份辨识度。用户明确指定玄幻修仙/仙侠/修真时，额外检查是否落实精致面料和层叠、门派/修行服制、灵纹或法器挂点、玉石金属织物材质分层及发冠簪饰固定结构；男主/女主还必须通过“装饰密度与成套度检查”：服装结构达到“结构丰富度多路径达标”（重工多层叠 / 半透纱罩层次 / 高开衩+披帛飘带 / 抹胸+外纱外套 / 腰封+腿饰绑腿结构 / 大氅披风+内层结构，任一路径成立即可，不设固定层数下限，也不得为凑层数强加无露出关系的衣层；判定见 `xianxia-manju-costume-library.md` 第5节）、主衣有定点工艺（盘金绣/织金/暗纹提花/缂丝感纹样/滚边等，不得“无纹样”或“仅同色暗纹”）、成套头面与成套腰部承载（腰封/腰带+腰佩玉或系带法器；“成套头面”指有主件＋明确固定结构，任选载体系族——冠族、钗簪族、额面族、束发族、垂饰族、自然族，见 `xianxia-manju-costume-library.md` §2.8，不指必须出现簪/钗/步摇，件数自由；载体须与发型联动，披发/散发角色不得硬插发簪；同作同类角色的头面须换族，不得照抄同一套）、主色+辅色+强调色+金属色分层，五类缺任一即判定未达题材下限，退回补足；“克制、素雅、清冷”只能降低装饰密度与色彩对比，不得作为取消工艺与成套配饰的豁免理由。同时按该库检查九槽是否逐项落到具体选值（廓形、纱质面料、层搭、露肤与开衩、外披肩部、鞋履、腿足点缀、头面腰佩、驱动来源），并逐条核对“同类型角色差异化硬约束”：同作同类角色须在至少四个槽位取不同选值，且必须包含廓形、层搭或纱质处理、露肤处理、鞋履中的至少两项；只换配色与花纹即判定不合格。该题材按 AI 漫剧定位，允许夸张、高华丽与非物理飘带、纱罩、开衩、腿环、足环、悬浮表现，不做汉服形制考据；只写“仙气飘飘、华丽、高级”等形容词而无具体纱质、开衩、悬垂、配色结构的，判定未完成。若没有剧情依据却出现粗麻、破旧、单层素衣，退回重写。另外核对：【避免】负向清单是否逐条写出且与所属分支一致（见 `xianxia-manju-costume-library.md` §3.2）。命名三段式、分节骨架与服装节顺序属该库实采的默认方向，项目已有命名体系/模板或用户另有要求时以其为准，不计入未完成判定。质量门缺任一判定未完成。

先写一句设计主张：角色希望给观众什么第一印象、服装所属体系、造型强度、主轮廓与主色关系。制服、私服、战装、礼服先确定；不得用“顶美、主角感、高级”代替可见设计。

用户明确指定都市/现代题材（都市言情、豪门、职场、娱乐圈、校园、都市异能等当代背景）时，额外按 `modern-manju-costume-library.md` 检查九槽是否逐项落到具体选值（廓形、面料、层搭、露肤与开衩、外层与肩部、鞋履、腿部层与袜、配饰承载、驱动来源），并逐条核对“同类型角色差异化硬约束”：同作同类角色须在至少四个槽位取不同选值，且必须包含廓形、层搭、露肤处理、鞋履中的至少两项；只换配色与款式名（例如两套都是“黑西装+白衬衫+西裤+黑皮鞋”）即判定不合格。检查是否按实采公式“颜色＋款式＋面料＋版型＋鞋包配饰＋画面要求”落词，而不是只写“高级、漂亮、优雅、帅气、时尚、精英感、氛围感”。核对是否逐条写了【避免】负向清单且与所属分支一致（见该库 §3.3）。命名三段式、分节骨架与服装节顺序属该库实采的默认方向，项目已有命名体系/模板或用户另有要求时以其为准，不计入未完成判定。同一角色多套场合造型须写明“保持参考人物的五官、发型和身材比例不变，仅调整服装与配饰”，不得写成换人。质量门任一项缺失判定未完成。同时确认该库未越界：发型、发色、妆面、脸型骨相、配色色名与饰品材质仍由 `hair-style-library.md`、`hair-color-library.md`、`eye-makeup-library.md`、`face-archetype-library.md`、`palette-costume-jewelry.md` 与项目视觉圣经独立取词；都市题材的华丽度不设题材下限，可由项目自由选择强度。另外核对：非职场精英分支不得把职业西装/三件套当默认品类——场合（公开/通勤/约会/晚宴/舞台/私下）只调整造型强度与装饰密度，不决定品类；都市女主级角色允许进入华丽档与微夸张档，不得仅因标注“公开场合”就退化成保守职场写实造型，但**微夸张指更华丽、更精致以突出主角或关键人物，不是把服饰写丑**：不得用怪异比例、畸形廓形、超大体积堆砌、无支撑悬浮结构或失真垫肩换取夸张；且**微夸张不是必需项**，走克制写实档同样合格，不得为凑档位强加夸张元素；同作同类女主不得共用 `palette-costume-jewelry.md` §1.6 的同一行配色方案，也不得按“清冷→冷白蓝、明艳→暖金红”的惯例自动二选一。

没有已确认的完整造型时，先做两套简短的整套候选，比较脸部衬托、服装协调与角色贴合度，选定一套后再展开提示词。候选是文字设计，不提交生图、不额外消耗生成额度。已确认造型只修指定问题，不重新随机换装。记录选中理由与弃用理由各一句，默认交付唯一完整成稿；用户要求对比时再展示候选。

男主定稿同步执行 `male-character-asset-design.md` §6，核对骨相、肩颈胸背、下装鞋履、头面腰部承载及同等级华丽度；不能仅检查女主。

## 2. 整套搭配的判断依据

| 检查对象 | 必须作出的设计判断 | 需要返修的情况 |
| --- | --- | --- |
| 面部与发型 | 骨相在正面和45度可读；刘海宽度、顶区体积、发长与脸长互相衬托，保留自然表情和角色辨识点 | 厚刘海遮五官；清冷写成病态；不同角色共用同一模板脸 |
| 领口与肩颈 | 领型、领带、项链、发尾的落点有主次；外套肩宽与体型相称 | 高领再叠多件颈饰、发尾遮满领口；学生因结构夸张变成舞台造型 |
| 上下装 | 腰线、衣长、裤裙宽度形成完整轮廓；叠穿有实际露出区域 | 为填内中外层强行加三件衣；上宽下宽却没有轮廓控制；所有衣层争抢腰线 |
| 裙裤、腿部与鞋 | 裙裤长度、袜口位置、露腿范围、鞋头与鞋底体量整体相称；按活动和穿着制度选择 | 鞋体量压过轻盈衣装；多道袜口与裙边切碎腿部；只因气质标签默认丝袜 |
| 色彩 | 明确主色、辅色、点色及衣物落位；近似颜色靠明度或材质分层，脸部保持可读 | 多种高纯度颜色等量竞争；发色、领口与肤色混成一块；只靠滤镜统一 |
| 材质 | 选择合适的软硬、厚薄、哑光与光泽对照，符合造型季节与强度 | 所有部位高亮如塑料；薄料承托无固定点重饰；轻装无故堆厚层 |
| 饰品 | 主饰与辅助件有主次；颜色、形状或工艺形成适度呼应 | 每处都加蝴蝶结、珠链或宝石；为了呼应重复堆满相同母题 |
| 主角与群像 | 主角在面部魅力、剪影或配色上有稳定识别点；配角完整好看，同作品彼此可区分 | 以饰品数量代替主角气质；配角丑化；多人仅换发色 |

架空古风宫廷主角需再核验社会等级的视觉可读性。公主主角常态造型至少有三类具体的宗室标记分布在头面、肩袖/外层、主衣纹样、裙摆轮廓、面料工艺或腰部成套珠宝；不能把“年轻、日常、灵动”误读为侍女级的轻便素装。该规则要求身份清晰，不强制使用凤冠、红金配色或大典礼服。

这些检查支持克制、华丽和混搭等不同方向，不把某种脸型、肤色、袜型或鞋型规定为国内观众的统一偏好。但“克制”只是气质与装饰密度选择，不取消题材下限：玄幻修仙、仙侠、修真与古风宫廷的男主/女主仍须满足 §1 的装饰密度与成套度检查。设计者必须说明具体部件为什么相配；仅因“库里有”而加入的部件应移除。若移除某个配饰后整体更清楚，优先移除。

## 3. 唯一造型记录与冲突检查

定稿前用一份 `character_design_record` 统一：年龄、骨相、渲染风格、发缝与束点、发色分区、衣层顺序、领肩结构、上下装长度、袜型与高度、鞋型、配色落点、饰品数量、人物自身左右、站姿、空手状态。记录还必须有 `library_inputs`（库文件、条目/段落、采用落词）和 `rejected_options`（舍弃候选及理由）。所有提示词段落均从这份记录展开；修改一项时同步修改描述、背视、锁定项和负向词。只写“用了发型库/服饰库”而没有具体条目，视为未完成。

```text
character_id / version:
visual_style / reason:
role_axes: world / identity / story_function / temperament / scene / action / state
library_inputs: file + section/item -> selected design detail
rejected_options: candidate -> reason
face_and_makeup:
hair_shape / hair_color_topology:
outfit_layers / lower_garment:
waist-shoulder-wrist / legwear / footwear:
accessories: item / material / position / attachment / length
palette_and_materials:
pose_and_empty_hands:
continuity_locks / known_unknowns:
```

逐项检查并修正后才可交付：

- 语义冲突：裸腿与连裤袜并存、半扎与全部盘发并存、同件衣物同时开襟和完全闭合、无饰品又佩戴项链。
- 结构冲突：短内袖不可能伸出长外袖；裙长覆盖袜口时不能要求全身图看清袜口；发冠、肩带、披帛互相穿透；鞋扣或包袋左右前后不一致。
- 视觉冲突：轻盈制服无理由配巨大鞋底或仪式披肩；面部被发饰高光与复杂领口抢焦点。混搭须有统一的轮廓、配色或材质依据，不以“混搭”免责。
- 正负向冲突：负向不得禁止正向已选的袜型、领带、制服、配饰或材质；修订后删除过时的负向限制。
- 资产用途冲突：16:9、同一人物四视图、全身完整、双手空置；不加入抱书、拿手机、扶剑柄、手提包或其他剧情持物动作。
- 模型输入冲突：每件物体只有一个确定版本，成稿不保留“或者、任选、同上”及未填占位；不将多套候选融合成一条提示词。

## 4. 交付与实际图像验收

交付前记录简短审核结果：调用库及采用部分、整套选择理由、冲突修复、未确认项。用户只要提示词时，直接给完整成稿，审核记录无需插入生图正文。存在硬冲突时先改稿，不能以总分或“整体好看”抵消。

文字审核只确认设计和描述一致，不能宣称实际建模已经好看或能保证留存。图像生成后另看胸像、全身与缩小后的辨识效果：先看脸和表情，再看剪影、配色、鞋袜与细节，检查四视图一致性。出现塑料肤质、比例失衡、焦点杂乱或服装失配时记录具体部位，按用户费用和确认规则修订。

平台趋势用于校准时，记录实际看过的作品、链接、日期、具体可见造型及适用观众；比较同类作品的不同人物，不从单条热门内容推出普遍审美。播放量不能单独证明服装导致留存，未查看的素材不记为研究依据。
