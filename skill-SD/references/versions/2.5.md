# Seedance 2.5 专属编译规则

版本说明：只使用 Seedance 2.5 对应的 provider 文档、输入结构和提示词；不要引用 Seedance 2.0 专属编译语法。

仅在项目已锁定 `seedance-2.5` 时读取。具体能力取决于当前provider、精确model ID及接入schema；不把社区提示范式或其他provider字段写成平台保证。不得引用2.0规则或MiniMax H3字段。

## 互斥输入模式

本项目把2.5制作分为三种结构互斥的模式，名称仅为内部分类：

- `text_only`：本job没有媒体参考输入。
- `reference_set`：通过当前接口已确认的参考图/视频/音频输入控制明确属性。每个输入需在清单标明用途和不控制范围；正文/请求映射不能把内部asset ID当平台槽位。2.5音频参考、声音生成或音色控制是否存在，逐项依据当前schema。
- `first_last_frame`：恰好一张起始帧图和一张结束帧图，均真实存在、经审核且比例为16:9；从首状态设计连续动作到尾状态。此模式不混入`reference_set`图/视频/音频槽。若服务提供不同于此模型的联合模式，先更新并验证本契约再用。

禁止将全参考与首尾帧在一个job、请求或资产清单里合并。若画面同时需要角色资产和首尾帧，先评估是否改走reference_set并用文字描述动作，或拆为独立且状态衔接的job；不能伪造混合输入能力。

2026-09-15的旧能力快照曾记录单次4–30秒、图/视频/音频数量上限及时间码描述能力；这些数字不得作为当前硬限制。每次核实精确provider和model ID的时长、素材类型/数量/总时长、输入角色、比例、声音和价格。2.5开源 Skill 还列举 Long Video、片段续写、Smart Edit/局部编辑、视频衔接和多格故事板等候选工作模式；这些只作为需要核验的候选，不是跨 provider 保证。能力存在也不代表要使用：玄幻仙侠武打默认不制作多格故事板图，改用逐镜头详细动作提示词。只有当前2.5接入明确提供对应模式和字段时才启用，并在job记录能力证据与输入输出映射。普通短片的推荐时长按剧情剪辑设计，不因存在长视频能力就把一个90–180秒剧集塞进单次生成。

Seedance 2.5以连续镜头/连续运镜描述时间过程；若故事需要真实硬切而当前服务不支持镜内剪接，拆成独立job并在剪辑阶段切换。镜头序列须落实通用分镜的人物画面比例、当前观察视点和切换因果，不能因为单条提示词要连续描述而把整段固定为中景；真正需要剪切的镜头按已核验接口能力拆job或后期剪辑。截至2026-09-15审阅的适配资料将含真实人物脸的上传图像/视频记录为平台限制；提交媒体前按当前provider政策重新确认。默认使用原创AI/CG绘制角色图，不将3D写实风格与真实照片输入混为一谈。

同一适配资料记录：全参考、首尾帧和视频编辑为互斥任务类型；首尾帧模式可能要求`adaptive/auto`画幅，且尾帧不能单独使用。若本次provider沿用此行为，只有首尾两张均为16:9且最终输出可核为16:9才通过画幅门，否则改用全参考或停止提交。实际参数名与限制仍以当前接口为准。

### 2.5 扩展模式候选（逐次核验）

当前provider若确实提供以下2.5功能，先选择一个有明确输入/输出契约的任务，再分别编译；功能不存在时从工作计划中移除，不模拟字段：

- **长视频生成**：用于单次请求确实支持的较长连续段落。仍按剧情段落分配动作与信息节拍，保持90–180秒为单集总长，不以长上下文替代镜头审查或后期剪辑。
- **续写/延长**：输入实际已审核片段，写清延续起点、继承的身份/空间/声音状态和新增动作；以服务实际接受的末态为准，不基于预想尾帧。
- **视频编辑/局部修改**：明确源视频、目标时间区间、保留内容与允许修改内容；先核实编辑范围、时长和是否会重生成未标记区域。源文件需为可审核版本。
- **片段衔接**：明确前后片段各自边界状态、过渡目标与接缝动作；先判断模型转换是否合适，直切、叠化或声音桥也可由剪辑完成。
- **多格故事板动画**：仅当2.5接口明确支持、题材工作流适用且用户明确选择时，才将已确认故事板按时间顺序绑定并说明各格顺序和连接动作。玄幻仙侠武打默认不使用；不得把多格板误称为首尾帧或单格锚点。

以上候选能力不改变2.5内既有输入模式互斥规则，也不与2.0共享字段。每次job必须记录 provider 能力证据、真实输入文件、任务类型、允许修改范围、费用和输出审核状态。

## 提示词编译顺序

每条提示词自包含且可直接复制。按故事需要组织，不要求所有镜头同一套僵硬七段标签：

1. **成片基准**：16:9横屏、项目已确认的媒介/渲染风格、色彩/材质/光线/景深基准。未定风格时先按题材选定方向，不默认国漫CG或写实。
2. **输入参考映射**：列文件实际用途，例如“锁定沈砚面部、黑发束冠、服装层次；不控制镜头构图”；只有request record真实映射后才能写作已引用。
3. **场景与构图**：环境锚点、景别、机位、角色位置、身体朝向、眼神目标、前后景关系。
4. **动作分拍**：起始状态、动作发起、路径、接触/避让、受力反馈、结束状态及环境响应。
5. **表演与对白**：可见表演与可听语气分开表达；冻结对白原句逐字不改，标出说话人和句间停顿。
6. **摄影路径**：运动类型、触发时机、相对被摄主体的移动轨迹、速度和停止位置；稳定镜头无需强加运动。
7. **声音层**：对白、环境声、动作音、画内声与画外配乐分清。只有当前模型支持并且本次选择使用原生符号时，才将自然语言序列化成对应声音通道。
8. **结尾与接缝**：末态可见可画，写出下一段需要的姿态/位置/道具状态和允许变化。

现有适配资料记录的2.5声音字符映射为：`<音效>`、`{台词}`、`(配乐)`、`【字幕】`。仅当本次官方/provider文档或成功实测确认同一映射时启用；不能只凭过往格式说明默认支持。启用时先记录每种标记对应的声道和作用域，按规范闭合并检查嵌套。未确认时整条提示用自然语言描述声音，绝不发明另一套映射。示意：`<石室滴水与布料摩擦声>`；`{沈砚（压低音量、语速平稳）：“阵眼还在，别碰那盏灯。”}`；`(低音弦乐由弱渐强)`；`【字幕：阵眼还在，别碰那盏灯。】`。示意不是接口保证；字幕也可交给后期，不为使用符号而强制内嵌字幕。

## 首尾帧专用检查

按当前schema明确首/尾帧文件上传映射、比例、允许的分辨率/格式和生效范围。首帧确立镜头起始构图，不应意外要求片段一开始已完成中途动作；尾帧须处于前面动作可到达的空间/身体/道具状态。动作路线必须有足够时间，不可要求瞬移补齐差异。首帧是时间序列中的真实镜头起始画面，不是角色身份板；需要身份参考时优先选择全参考模式，或只用当前接口明确提供的分离映射。

两帧都是16:9。不要让角色、服装、场景或伤损的设计变化夹在两端，也不要将角色资产板误当成时间序列的第一帧。平台如果要求`auto/adaptive`等比例参数，只有它与最终16:9约束可同时满足时才提交，否则阻断并改用已核验的输入模式。

## 全参考专用检查

为每份参考记录：`asset_id / input_role / path / purpose / does_not_control / aspect_ratio / reviewed_status`。角色四视图板用于身份、妆发、衣装和配饰稳定性；场景结构图用于空间；动作视频只在schema接受且它确实用于动作时使用；音频只有当前2.5 provider确认支持时用于相应声音目的。每个素材至少在正文被有效引用一次，低贡献和未使用的输入应从本job移除。

参考图与视频构图不应无意中取代分镜计划。若参考图只控制角色身份，就明确当前镜头的景别和姿势；不要用“照着这张图”覆盖身份、动作、风格、摄影等互相竞争的意图。

## 对白与声音

语气要可听见且具体，例如“压低音量、语速慢、句尾收紧”；可见表情写在画面动作中。OS/VO注明声音是否来自画面外和画中人物嘴部状态。冻结台词与实际镜头分段回拼必须逐字一致。

若当前接入确认原生对白/音效/音乐符号，符号只用于它规定的声音通道，不把画面动作塞进音频通道，不把台词再次重复进环境声或配乐字段。真实上传的音频参考需标用途，未提供的配音演员或参考音频不能写作已锁定音色。

## 时间戳精确规范

Seedance 2.5 支持**整秒级精确时间戳控制**，这是相比 2.0 的核心升级。

### 时间戳精度与最小间隔

- **精度要求**：秒级精确（如 `0.0s`, `4.0s`, `8.0s`, `12.0s`）
- **最小间隔**：3–4 秒以上，避免过密的时间戳导致模型难以生成清晰过渡
- **最大单镜时长**：不超过 10 秒；建议 4–5 秒为一个干净节奏单位
- **最优拍数**（12 秒视频）：4–5 拍

**时间戳写法三种格式**：

1. **区间式**：`[0.0s-4.0s] 女主转身离开，背影走向门口`
2. **时间点式**：`4.0s: 镜头切换至男主特写`
3. **相对式**：`接下来的 3 秒：男主沉默低头`

### 节奏分段规范

单次时长以**当前渠道 lock** 为准，不要使用社区「30 秒旗舰」数字。把长段落按剧情切成渠道允许的拍。四段式节奏（建立→发展→转折→收束）只作为剪辑结构参考，不是接口保证。未核实的 30 秒/50 参考/MOV/口型 99% 等说法见 `references/research-basis.md` 待核验区。

### 硬切时间戳规范

硬切（Hard Cut）仅在指定整秒时间戳处执行，如：

```
4.0s: 硬切至特写镜头
8.0s: 硬切回全景
12.0s: 硬切至反应镜头
```

**禁忌**：不要在非整秒时间戳处执行硬切（如 `3.5s`, `7.8s`），会导致模型生成不稳定。

## 多轮延长工作流

延长/续写与参考数量以当前 provider schema 和渠道档案为准。社区「50 个多模态参考」不得写入请求。能力未核实则按 baseline 截断（见 `models/seedance-2.5.baseline.json`）。

### 延长模式核心机制

- **首帧延续方法（Pro 工作流）**：取前一个片段的**最后一帧**作为新生成的**首帧**
- **新 prompt 要求**：首 1 秒仅描述**微动作**（micro-movements），避免剧烈变化导致跳帧
- **两帧尺寸共享**：首尾帧必须共享相同尺寸，避免拉伸

### 延长工作流步骤

1. **生成第一段**（如 0–12s）：
   ```
   [0.0s-4.0s] 女主站在窗前，微风吹起窗帘
   [4.0s-8.0s] 镜头推进至女主侧脸特写
   [8.0s-12.0s] 女主缓缓转身
   ```

2. **提取最后一帧**：从第一段视频的 12.0s 位置提取最后一帧

3. **生成第二段**（12–24s）：
   ```
   首帧：使用从已审核片段抽出的真实末帧文件（不要使用未核实的 `[@image_last_frame_12s]` 槽位名）
   [12.0s-13.0s] 女主保持转身姿态，仅眼神微动（micro-movement）
   [13.0s-17.0s] 女主走向门口
   [17.0s-24.0s] 镜头跟随女主背影，她推开门
   ```

4. **后期拼接**：使用专业视频编辑软件对齐关键帧，修复连接点处可能的微小跳帧

### 延长失效常见案例与修复

| 问题 | 症状 | 修复方案 |
|------|------|----------|
| 连接点跳帧 | 屏幕位置跳跃、回滚 | 后期软件对齐关键帧 |
| 最后帧延续失效 | 颜色保留但空间重构错误 | 必须正常速度播放审核，及时发现 |
| 首 1 秒剧烈变化 | 首帧延续断裂 | 强制首 1 秒仅微动作描述 |

## 概念分镜与关键帧设计

Seedance 2.5 支持**概念分镜**（Concept Storyboard）与**关键帧驱动**（Keyframe-driven）工作流。

### 概念分镜工作流

1. **绘制草图或使用 AI 生成关键帧**：
   - 工具：Midjourney、Stable Diffusion、手绘草图
   - 输出：3–5 张关键帧图像，代表视频的关键时刻

2. **标注时间戳与动作**：
   ```
   [@image_keyframe_1] 0.0s: 女主站在窗前，侧脸特写
   [@image_keyframe_2] 4.0s: 女主转身，全身镜头
   [@image_keyframe_3] 8.0s: 女主走向门口，背影
   ```

3. **提交 Seedance 2.5 生成**：
   - 模型根据关键帧图像和时间戳，自动插值生成中间过渡动作
   - 生成结果会精确落在指定时间戳的关键帧位置

### 关键帧设计最佳实践

- **关键帧数量**：3–5 张（30 秒视频）；2–3 张（12 秒视频）
- **关键帧间隔**：4–8 秒，避免过密
- **关键帧一致性**：角色服饰、场景灯光需保持一致，避免模型混淆
- **首尾帧锁定**：
  - **首帧**：锁定输出视频的宽高比
  - **尾帧**：定义视频结束时的精确画面
  - **首尾帧组合**：定义端点，模型生成精确落点的运动路径

### 关键帧驱动 vs 纯文本驱动

| 工作流 | 适用场景 | 优势 | 局限 |
|--------|----------|------|------|
| **关键帧驱动** | 复杂动作、精确构图、多角色场景 | 画面控制精确、空间关系清晰 | 需预先制作关键帧图像 |
| **纯文本驱动** | 简单动作、单人场景、快速迭代 | 快速、灵活、无需额外工具 | 复杂场景难以精确控制 |

**建议**：玄幻打斗、多人群戏使用关键帧驱动；文戏对话使用纯文本驱动。

## 提交前门

- 整个项目和每个job都锁定`seedance-2.5`。
- `reference_set`与`first_last_frame`输入严格互斥；`text_only`没有媒体附件。
- 当前provider确认模式、素材角色、时长、格式、尺寸、16:9和费用。
- 每个输入文件能读取、比例符合、审核状态合格、用途清楚并被实际提示词引用。
- 原生声音标记仅在当前schema提供证据后启用，否则用自然语言。
- 对白逐字、镜头覆盖时长、首尾状态可达性、段缝与输出画幅已检查。
