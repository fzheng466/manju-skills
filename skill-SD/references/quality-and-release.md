# 质量门、审片与交付

质量门用于阻止错误进入下游，不是额外审批链。按用户当前范围完成所需门；局部任务不必伪造整季交付材料。

## 阶段门

| 门 | 通过条件 | 不通过时的动作 |
|---|---|---|
| G0 范围与来源 | 模型锁定、16:9、目标交付与来源材料清楚；事实/推断/补全/未知已区分 | 补齐会改变制作路线的缺项；不把未知写成事实 |
| G0a 生成授权 | provider提交的job ID与用户授权集合完全一致，且记录授权证据和预算上限 | 保持draft；列出需要授权的job与预计费用，不自行代填授权 |
| G1 故事冻结 | 因果链可复述，关键选择/信息揭露/伏笔有落点，台词原句有稳定 ID | 最小化修订并维护覆盖表；无法判断原意时提问 |
| G2 资产可用 | 关键人物/场景/道具已有可定位的实际资产，或明确标记待补；风格与资产状态相符 | 不在视频提示词中声称引用不存在的图 |
| G3 分镜可执行 | 时间线完整、空间/视线/持物状态可追踪、动作可拍、声音归属明确 | 修正涉及镜头和直接相邻镜头，必要时做预演 |
| G4 模型编译可校验 | 当前版本模式和输入映射匹配；参考引用有效；台词、声音层、时码及画幅符合对应profile | 留在草稿并修复；不转成另一模型语法 |
| G5 生成记录完整 | 真实任务ID、输入文件、参数快照、结果路径和版本关联到job | 状态停留在submitted或failed，不虚报生成成功 |
| G6 内容审片 | 逐镜观看实际媒体，按时间码记录身份、空间、动作、对白/口型、声音、特效问题 | 只返修失败镜头与受影响邻镜；保留旧版本 |
| G7 技术验收 | 实测文件画幅16:9；核对分辨率、帧率、时长、音轨、字幕、端点和编码 | 报告实测值与失败项；不以计划参数代替文件检测 |
| G8 交付状态 | 交付物、版本、审核状态、未完成项、已知限制、来源和复现线索清楚 | 以草稿/部分完成标示，不能称最终成片 |

## 逐镜审片表

每项缺陷记录 `shot_id / media_path / timecode / category / expected / observed / severity / fix_scope / reviewer / reviewed_at / disposition`。建议严重度：

- **阻断**：错误身份或服装、关键剧情动作不可读、致命轴线/方位错误、对白丢失/被改写、比例错误、素材损坏或侵权/授权状态未知且用户要求发布。
- **主要**：空间跳变、动作受力不成立、关键表演不清、口型与声音明显错位、连续性物件漂移、特效遮住剧情信息。
- **次要**：局部材质/光影波动、非关键细节漂移、可在剪辑/调色/混音解决的小问题。

标签不是自动裁决。最终交付必须人工播放实际媒体；脚本只能验证结构、文件存在与部分技术值，不能判断演技、内容质量或“看起来一致”。

人工审片加问：

- 非持有者在场时，私有特效是否已经收起？
- 侧身或过肩时，特效有没有挡住身体或对话对象？
- 同一 `voice_profile_id` 跨镜是否明显换声？
- 台词逐字是否经过 ASR 或人工核对？没核对就标「未验收」。
- 场景是否只用了单格参考？
- 道具状态是否与 ledger 一致？

## 连续性复验

角色/服装/道具状态更改后，查询使用该资产的所有镜头；场景结构和光源变化后，复验同一空间家族的构图及时间段；台词或声音修改后，复验前后停顿、口型、字幕和音乐切点。只复验直接受影响项目及相邻接缝，但记录搜索范围与结论。

任何已通过的镜头在复用或重新剪辑时都要检查新的前后关系。资产板只锁角色外观，不代表某镜头的姿势、景别或构图；审片按当前镜头意图对照，不把设计板误当视频关键帧。

## 交付清单

按用户要求选交付项，并在清单中标记 `done / pending / not_applicable`：冻结剧本和覆盖表；视觉圣经和资产账本；角色/场景/道具提示词与真实图像路径；分镜/声音/字幕表；锁定版本与提示词版本；能力核验证据；提交与生成ID；生成媒体及审核表；剪辑/混音/字幕计划；最终成片实测规格；未解决问题、预算使用、修订历史和发布状态。

## 状态词汇

`planned` 仅为计划；`assets-ready` 表示输入文件已实际检查；`submitted` 表示服务确已接受请求；`generated` 表示结果文件已落地；`reviewed` 表示人员看过实际结果并留下审核记录。`approved`仅适用于明确通过的资产/镜头；`released`仅在发布动作确实完成后使用。机器校验通过不自动推进这些状态。
