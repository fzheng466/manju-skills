# MiniMax H3 漫剧制作

## 第一步：先锁画幅，再面谈渠道（强制）

调用本技能后，在写资产图或 H3 提示词之前：

1. 读取 `_core/references/channel/interview.md` 与 `_core/references/assets/aspect-tracks.md`。
2. **第一问：这次交付 16:9、9:16，还是两条都要？** 写入 `deliverables`。人物身份四视图可共用；构图资产、镜头提示词按线生成。
3. 再选渠道（`$MANJU_HOME/channels`）。一条线渠道不支持该画幅时，只暂停该线（换渠道 / 等待 / 衍生版），**不改另一条线已定稿资产**。
4. 生成 lock：`python -m core.lib.lock --project project.json --channel <id> --baseline models/h3.baseline.json --out effective-capability.lock.json`
5. 提交前必须：`python scripts/validate_project.py project.json --lock effective-capability.lock.json`
6. 大纲/原创/改编先读 `_core/references/story/SKILL.md`。

动漫/3D 战甲、仙袍、头饰流苏资产图读取 `_core/references/assets/anime-3d-asset-lexicon.md`，不要只用真人缂丝/盘金绣词。生图前跑：

```text
python -m core.lib.asset_prompt --kind character --aspect 16:9 --sex male --character-id SHEN_YAN --file asset-hero.md
python -m core.lib.identity --project project.json
python -m core.lib.asset_prompt --kind weapon --aspect 16:9 --sex male --character-id SHEN_YAN --file artifact.md
python -m core.lib.shot_quality --job project.json --job-id JOB001 --prompt compiled.md
python -m core.lib.adapt --job project.json --lock effective-capability.lock.json --job-id JOB001
```

人物卡必须锁 `presentation_sex`（male/female）；服装和道具必须 `owner_id`。禁止把男角色的战甲/兵器提示词套到女角色，也禁止把女装、步摇、细跟套到男角色。规则：`_core/references/assets/identity-lock.md`。渠道只问本机 `$MANJU_HOME/channels`，真实入口不进 GitHub。

失败模式 `_core/references/failure-modes/failure-modes.md`。剧本层交接若有 JSON，对齐 `_core/schemas/handoff.schema.json`。

## AIKSK 本地提示词编译模块

本 Skill 已融合中文的 H3 模式约束、Director 逻辑和武打编排模块。涉及 `T2VA/I2VA/FL2VA/L2VA`、`Ref2VA`、多图参考、双人攻防或兵器时，先读取 `references/aiksk-local-prompt-integration.md` 和 `references/h3-mode-constraints.md`。

融合模块的官方语法优先级、素材语义映射和武打工作流作为本 Skill 的 H3 编译增强层；它不能覆盖本文件对交付画幅（16:9 / 9:16）、90–180 秒整集、资产状态、导演谱、生成授权和逐张资产确认的约束。AIKSK 规则属于生产启发式，不能表述为 MiniMax 官方要求。

## 目标与隔离

本技能面向以 MiniMax H3 生成视频的漫剧，交付画幅由开场第一问锁定（16:9、9:16 或两条都要）。H3 的模式、字段、说话人标签、对白标签、图像/视频/音频引用和调用参数只由本技能管理。不得先套 Seedance 七段式，不得将 Seedance `<> {} ()`、上传槽位、时长或素材额度转换成 H3 能力。

所有测试和测试产物统一写入 `$MANJU_HOME/test-runs/`（默认 `~/.manju/test-runs/`），不得在项目目录、仓库目录或项目的 `00_brief` 至 `07_qa` 目录内创建测试文件、测试提示词、测试请求、测试图片、测试视频、测试音频、抽帧、日志或测试报告。这里的测试包括全流程试跑、单段视频测试、H3提示词测试、资产图提示词测试、资产图生成测试、参考绑定测试和校验器样例。项目源码、参考库和正式生产项目文件仍按本 Skill 的项目目录保存；只要用途带有 test、dry-run、试跑、预演、样例或验证，就必须放到外部测试根目录。

外部测试目录使用以下固定结构：

    03_video-tests/

每次测试建立一个批次目录 `YYYYMMDD-HHmmss_<kind>_<slug>`，其中 `<kind>` 使用 `prompt`、`asset`、`video` 或 `pipeline`。测试文件名包含稳定 ID 和版本，例如 `asset-hero-v003_prompt.md`、`job-002_test-v001.mp4`。测试记录必须写明 `project_id`、批次目录、输入来源、提示词版本、模型/通道、是否实际调用、费用和结果状态；项目清单中的 `path`、`compiled_prompt_path`、`request_record_path` 若指向测试产物，必须使用该外部路径，不得回写成项目内路径。

如果用户明确调用 `$minimax-h3-manju` 或明确说“走 MiniMax H3”，视为已选 H3；若用户只说“跑总流程/做漫剧”且未选模型，则先询问本次走 Seedance 2.0、Seedance 2.5 还是 MiniMax H3，得到回答前不写模型投喂词、不提交生成请求。若用户明确选择Seedance，停止当前H3流程并提示使用 `$seedance-manju`；不在H3内代跑另一条流程。

全项目画面按开场锁定的交付线执行（16:9 / 9:16 / 两条都要），规则见 `_core/references/assets/aspect-tracks.md`。角色资产默认每人一张人物四视图板：左侧为超大正面胸像，右侧并排正面全身、45°侧向全身、背面全身；只在结构识别确有需要时把45°替换为严格侧面。不要默认额外制作头像、九宫格、表情板或多次独立人物图。身份四视图可跨画幅共用；构图资产与镜头提示词必须按交付线分别生成。
人物四视图资产板双手空置，不手持、怀抱或提举任何物件。武器、书、手机等剧情道具另在道具资产与分镜中登记；镜头需要持物时再指定持物手和动作。袜类按 `references/palette-costume-jewelry.md` 的覆盖长度、织法、渐变、装饰与鞋履关系组合，不预设黑丝、白袜或任何单款。

完整单集成片固定为90–180秒，H3单个生成段为4–15秒；单场、单镜和局部试作标为非完整单集。剧本与分镜均按集内时间码覆盖整集，不用空镜、展示性运镜或重复反应填补时长；每段应推动目标、信息、关系或阻碍。

## 执行原则

- 用户提供的剧本、对白、角色定稿、参考图及既有项目状态优先。先读实际文件与图像内容；未打开/无法查看的资产标为待核，不依据文件名宣称已经核验。
- 先做必要依赖，后做下游产物；沿用已完成且仍匹配的工作，避免重复生图。只做用户要求的阶段，不把局部任务扩成整季。
- 预制作、提示词、生成任务、生成结果、审核通过、发布批准是不同状态。绝不把计划/提示词说成已生成，把生成说成已审核。
- 台词以冻结剧本逐字传递，所有分段按 utterance ID 拼接后与原句比较。改编只能发生在剧本冻结之前；后续模型编译不得润色或删句。
- 做图/视频/API 请求前检查当前工具和服务真实支持的模式、字段、参数、尺寸、时长、素材槽位、费用与重试预算。能力证据未核实时只交草稿，不猜接口；不自动回退其他模型。
- 不是所有镜头都要资产板或复杂运镜。按资产复用风险和空间复杂度安排素材，先用文本/低成本预演暴露问题，再生成正式内容。

## 制作流程

### P0 项目门

完整单集目标时长必须在90–180秒内；局部任务标明非完整单集。区分集内时间码与H3单段时间码。

确定用户范围、H3工作流、交付画幅（16:9 / 9:16 / 两条都要）、主/次题材、关系类型、视觉主媒介、语言、单集目标时长、交付物、已给材料、预算/返修限制。题材选择后按需读取 `references/genre-production-matrix.md`，创建 `genre_card_id`，登记观众承诺、故事循环、本集状态变化、规则/资源/关系/能力账本、复用资产家族及连续性锁定；混合题材分别维护规则，不互相覆盖。只有用户明确要求对指定job ID执行生成并确认预算上限，才记录生成授权；“跑完整流程”或索要提示词不等于允许提交。只追问会改变制作决定且目前无法推断的缺项。列事实、推断、设计补全、未知；记录原文授权/改编范围与素材来源声明，不自行作法律结论。

### P1 故事与剧本

剧本写完或收到现成剧本后，冻结前执行 `references/script-review.md`：按材料范围选择单场盲审或跨集审查，逐条核对因果与信息、人物选择与关系、道具和空间连续性、可视听表达及制作难度。每个问题都要有场次和原句证据、观众影响、严重度与最小修补方案；缺前情时列待核条件，不把未知判成硬伤。用户只要审查时交诊断与改法提案；用户要求改写时保存原稿，改后重审受影响场次。完整单集冻结前核验累计90–180秒；不足或超出时调整有效剧情或拆集，不以展示镜头凑时长。

按输入类型走原创构思、小说改编、现有剧本诊断或局部修订。先整理人物目标、阻碍、代价、世界规则、事件因果、信息揭露和结尾回报；长文本先建立原文/事件/场次覆盖表，并区分客观事实、角色认知、创作补充和未知。类型引擎、子类型关系推进及种田/末世/怪谈/异能/高武/古风的专属台账按需查 `references/genre-production-matrix.md`；每场引用 `genre_card_id`，把触发证据、人物选择、因果结果和账本变化写进可拍 beat，不能以题材名代替因果与人物选择。将剧本写成可拍场次，按目标、阻碍、行动、反应、策略变化和结果检查场景推进；对白保留说话者意图、实际措辞及听者回应。台词、OS、VO、画内文字分别标明说话者与用途；有固定发声的角色建立稳定 `voice_profile_id`，把身份声线和单句情绪表演分开，并跨场、跨 job 复用身份锚点。场次标清情绪起点、触发、变化/压制与结束状态。人物音色档案与跨段一致性按需查 `references/voice-profile-and-continuity.md`；表演情绪拆解和分镜微表情规范见 `references/directing-and-continuity.md`；剧本、对白交锋、时长估算与情绪曲线字段见 `references/story-development.md`。冻结剧本前校验因果、人物知识、情绪推进、时长承载、伏笔与结尾；无法在90–180秒内完整承载时调整有效剧情或拆集，不悄悄删情节。

### P2 视觉圣经与资产

人物、场景、法器和武器提示词起草前读取 `references/visual-style-and-asset-modules.md`，按“资产类型→视觉风格→题材身份→环境状态”组合短模块；国漫、BJD、UE5、PBR 都是可选维度，不得写死为默认。人物资产风格以项目视觉圣经和用户明确指定为准；`references/character-prompt-style-variants.md` §2 提供常用增减示例，不构成封闭白名单。换风格时保留完整角色设计字段，只改渲染、材质、比例、光线等风格相关表述。

人物提示词必须通过 `references/character-styling-review.md` 的整套造型定稿与一致性审核：按角色需求调用库，比较完整搭配后选定唯一方案，记录 `character_design_record`（实际库条目、采用落词、舍弃理由），核对轮廓、妆发、配色、鞋袜、饰品及正负向冲突，再交付。未明确写“配角”“NPC”“路人”“侍从”等角色层级时，默认按男主/女主的高精美、高完成度标准编译，不得自行降成普通路人或粗麻烂布造型。不得随机抽库拼装，也不得以“字段齐全”或一句“参考发型/服饰库”代替实际设计。

人物四视图提示词按 `references/character-prompt-style-variants.md` 执行：基座骨架→风格增减→题材身份槽→角色专属轴→正负向冲突检查。该文件是既有素材库的编排层而非替代，各槽位按其§1.1映射表从对应库取词，只读模板不读库判定为标签替代设计。换风格只改增减内容，基座十一个槽位不动；同一作品多名核心角色须落在不同骨相、气质、腿部层与鞋型组合上，不得套用同一段。P3/P4 中每个含该角色的镜头提示词复述其两项稳定识别点（§10.1）。

先建立风格板：按交付线画幅、主媒介、线条/渲染、材质、色卡、光比和禁用的混搭风格。每个人物资产提示词起草前，必须读取 `references/character-archetype-wardrobe-library.md`，将世界条件、社会身份/职业、剧情功能、角色层级、气质、个人审美、关系阶段、当前场景、行动需求、天气/危险和当前状态作为独立轴组合，再编译完整 Look Card。默认角色层级为男主/女主；只有用户明确写出“配角”“NPC”“路人”“侍从”等词时，才启用配角的视觉竞争降级规则。默认高精美要求完整剪裁、清晰材质、精致妆发、成套可辨饰品和稳定识别点；粗麻、破旧、单层素衣必须有身份、资源或剧情状态依据，不得作为未指定层级时的默认。若用户明确说“玄幻修仙”“仙侠”“修真”，自动采用仙侠高精美方向，落实门派/修行服制、精致面料与层叠、灵纹或法器挂点、玉石/金属/织物材质分层、发冠/簪饰固定结构和有来源的灵性细节；玄幻修仙的男主/女主另有默认开启、不可削减的题材下限：服装结构达到“结构丰富度多路径达标”（重工多层叠、半透纱罩、高开衩+披帛飘带、抹胸+外纱外套、腰封+腿饰绑腿结构、大氅披风+内层结构中任一路径成立即可，不设固定层数，也不得为凑层数强加无露出关系的衣层）、主衣在领缘/门襟/下摆等定点有可描述工艺（不得“无纹样”或“仅同色暗纹”）、成套头面与成套腰部承载、主色+辅色+强调色+金属色分层，且“克制、素雅、清冷”只降装饰密度与色彩对比、不降材质与工艺等级（细则见 `references/character-archetype-wardrobe-library.md` §1.0）。玄幻修仙/仙侠/修真另按 `references/xianxia-manju-costume-library.md` 的九槽组合（廓形、纱质面料、层搭、露肤与开衩、外披肩部、鞋履、腿足点缀、头面腰佩、驱动来源）与角色分支（仙子/圣女/女宗主/剑修/仙君/魔君/妖皇/妖姬）生成，按 `references/modern-manju-costume-library.md` 的九槽组合（廓形、面料、层搭、露肤与开衩、外层与肩部、鞋履、腿部层与袜、配饰承载、驱动来源）与角色分支（清冷千金/温柔初恋/明艳主角/学院/职场精英/霸总权贵/温柔男友/偶像艺人/街头轻亚/都市异能/晚宴礼服）生成，按实采公式"颜色＋款式＋面料＋版型＋鞋包配饰＋画面要求"落词，禁止以"高级/漂亮/优雅/帅气/时尚/精英感/氛围感"等形容词替代具体设计；同作同类角色须满足该库第4节的结构层差异化硬约束，不得只换配色与款式名；同一角色多套场合造型须写明"保持参考人物的五官、发型和身材比例不变，仅调整服装与配饰"；【风格类型】行按题材分派并全剧统一——都市/现代题材默认 `高精度3D半写实BJD人偶`，玄幻/修仙/古风题材默认 `3D半写实国漫CG`（用户 2026-10 拍板），项目视觉圣经或用户指令可覆盖，覆盖后全剧一致；质感词（UE5/PBR/8K/高级CG）只作修饰，不得取代类型行。凡俗、外门、受伤、逃亡等降级状态须由剧情明确。题材仍不替代角色身份和行动需求。允许灵异甜妹、末世明星、校园虐恋等交叉组合。校园角色先核对项目校服/私服设定、学段和季节；明确学院制服时保留制服套系，通过合身度、妆发、配色和姿态突出角色，不擅自改成混搭时装。腿部层与鞋型独立选择，光腿、短白袜、普通薄底鞋都可成立，黑丝袜和厚底大头鞋不得自动加入。再读取 `references/face-archetype-library.md` 独立选择脸型骨相路径和气质表达，并检查同作品角色区分度。甜美气质不绑定圆脸。之后读取 `references/visual-assets.md`、当前组合实际需要的 `references/palette-costume-jewelry.md`、`references/face-design-and-opulence.md`、`references/hair-style-library.md`、`references/hair-color-library.md` 和 `references/eye-makeup-library.md`；存在额彩/花钿/面纹/印记时读取 `references/facial-markings-library.md`，没有则明确记录为无。按角色选择适用细节，不把整库词汇堆进提示词；将脸型五官、气质可视表现、妆发，以及完整服装搭配写入同一张人物四视图提示词。服装搭配必须明确上衣全部衣层、下装裤/裙/裙裤结构、腰肩腕部承载、鞋履、袜类/腿部层、饰品与头发；不能只写上衣或身份标签，不输出独立妆发板或脸部板。若生成结果反复偏圆，按脸型库的骨相几何与词汇冲突步骤修正，不以重复添加“瓜子脸/小脸”代替。

资产顺序按复用与风险决定：核心人物→关键场景/空间锚点→剧情道具→必要状态变体。人物、场景和道具提示词除各自资产库外，按题材读取 `references/genre-production-matrix.md` 的资产字段；从中选择本角色/地点实际需要的细节，不把库全文堆进提示词。场景再读取 `references/scene-direction-library.md`，覆盖现代都市、古代宫廷、玄幻修仙、武侠江湖、末世灵异、校园言情与未来科技，并结合具体空间锚点、材质、光源、色彩和剧情状态落词。玄幻修仙的男女主本命法宝或关键法器还需读取 `references/xianxia-hero-artifacts.md`，允许有炼器规则支撑的超现实形制；普通NPC武器不套用主角级复杂度。武器资产板按主线画幅出图（16:9 时横屏左主图右细节；9:16 时竖屏上主图下细节）；主图与细节区比例按细长、宽展/重型、短小密集或多组件器型选择，遵循 `references/visual-assets.md` 的比例区间，并在提示词中写明左右占比、主图完整范围及各细节窗内容。角色资产默认四视图一张；场景先按剧情判断大/中/小尺度，再分家族、区域、固定结构、状态变化与可用机位；道具记录比例/握持处/开合状态/左右挂点。每项写稳定ID、版本、证据来源、实际路径、用途、允许变化、父版本与状态。预制作文字可以标“待补”，不得伪装成已有图。

全部资产提示词定稿后，用户一句“开始生图/按清单生图”即可启动逐张实际生成，不要求重复粘贴提示词。必须走 `python -m core.lib.asset_gen next --project project.json --channel <本机档案id> --budget <n>`，确认后再加 `--confirm`。每次仅生成一张当前交付线画幅的资产图；参考图绑定依据身份/结构连续性自主判断，并在调用前告知参考资产与用途。每张生成后展示结果、等待用户确认，再进入下一张。费用、失败重试和禁止轮询规则见本技能自有副本 `references/sequential-asset-generation.md`；不得批量并行、轮询或自动重试。真实渠道只问本机 `$MANJU_HOME/channels`。

### P3 导演分镜与声音

镜头编排必须落实 `references/directing-and-continuity.md` 的人景比例和观察视点规则：每场确定焦点拥有者及其注意目标；每镜记录景别、人物/关键主体约占画面高度的比例、前中后景锚点、主客观视点和切镜理由。通过环境建立、动作全身、主观目标、反应和关键细节等景别变化呈现剧情；不允许整场默认中景。比例仅为构图参考范围，偏离时标注叙事原因。

每场戏先明确主要观察角色、其正在关注的目标、本场状态变化及焦点移交原因。每个 beat 交代可见触发、环境或人物动作、结果，以及下一 beat 如何承接；引用对应 `genre_card_id`，记录空间尺度、场景资产锚点、继承状态和本镜允许变化。切镜、近景和运镜须让观众读到新信息或动作结果。题材相关的生产/资源、规则/线索、关系、能力、修炼、礼仪权限或动作账本映射到本场有效 beats 和状态变更；只使用当前镜头可观察的信息。水、风、雨、灯火和活物按来源、路径、持续状态和人物反应设计，并跨镜继承；不能凭空增删。打斗按起手、应对、接触、反馈与新站位构成清晰动作链。具体执行见 `references/directing-and-continuity.md` 和 `references/genre-production-matrix.md`。

完整单集分镜的集内时间码必须连续覆盖90–180秒；每个H3生成段另记4–15秒的段内时间码，并写明前段末态与后段起态。每段推动剧情，不以展示性镜头填充。

先核验实际可用资产，再做分镜。每个镜头逐项登记所用角色、场景、道具及用途；最终 H3 job 的提示词只能绑定到账本中真实存在且审核通过的资产，并在附件清单中映射到对应文件和用途。不得只在文字里声称“参考角色资产”却不把图像作为模型输入。导演谱中的身份、场景结构和道具状态须与绑定资产一致；镜头专属动作、表情和构图由提示词另行说明。每个正式 H3 job 先写导演谱和连续性状态账本，再写模型提示词；不得从剧情梗概、文学剧本或只有“动作+语气+运镜”的粗分镜直接编译。导演谱必须把 job 全时长连续拆成 beats，并完整记录 `continuity_ledger`、`entrance_order`、`camera_plan`、`performance_plan` 和对白导演字段。每个 beat 都要给出时间窗、可见动作、人物相对场景锚点与画面区域、身体朝向、视线、可观察微表情、摄影机状态、声音和结束状态。

按镜头叙事目的、信息变化、空间复杂度和动作难度拆段；每镜记录：shot ID、起止时间、唯一主要可见动作、画面主体、景别/机位/运镜、人物位置与视线、表演触发与变化、对白原句/语气/`voice_profile_id`、环境与动作声、入镜态、出镜态、与前镜的连续性链接。首次相遇、伏击、惊吓和身份揭示必须逐人规定初始可见性、揭示触发、首次可见时间、移动路径和到达位置；未到出场点的人保持完全画外或完全遮挡。人物表情按剧情触发和强度变化具体到眉眼嘴、呼吸与身体反应；对白声线变化以角色音色档案为基线，没有必要时不额外制作表情资产。镜头秒数与 H3 单次任务时长分开管理。

动作使用“准备/重心→路径→接触或避让→受力反馈→结束姿态”；法术使用“来源→聚集/成形→传播→命中/作用→消散/残留”。玄幻战斗、斗法或能力型 job 还须建立战斗账本，记录优势证据、攻防交换、能力生命周期、唯一峰值、环境反馈和下一动作接口；具体规则见 `references/action-sound-edit.md`。视线、持物手、空间左右、画面左右分别记录。近景不同时承担全空间说明。一个短 job 若同时承担多人走位、精细道具交互、情绪转折、完整对白和多次切镜，必须删减或拆 job；10秒内不得用一句提示词强塞完整相遇、冲突、反转和多轮对白。表演参考、镜头语言与连续性细则见 `references/directing-and-continuity.md`；剧本至job的段卡、动作与台词负荷、跨段交接、审片和最小返修必须执行 `references/h3-episode-production.md`；武打、法术、声音、剪辑见 `references/action-sound-edit.md`。

### P4 H3 编译

正式视频编译以已审阅的导演谱和镜头表为准。玄幻仙侠武打不制作或要求多格剧情故事板图，改用逐镜高细节动作、表演、特效、声音和接缝提示词；其他题材只有在文字镜头表无法核清剧情顺序、且图片预演有明确收益时，才按需读取 `references/storyboard-preflight.md`。故事板不是默认阶段，单张最多24格的限制只在确有必要且用户选择制作故事板时适用；故事板确认不等于视频生成授权。

漫剧剧情场景默认须有已核对的四向结构基准板（结构板可按主线画幅制作），记录世界轴线、机位方向和固定锚点；9:16 交付线从对应格裁中心竖条或单独出竖幅场景图，禁止拉伸。单机位场景只使用已确认的可见范围。四向板结构不一致时不声称空间已锁定。编译前人工审阅场次焦点、切镜理由、环境动态因果与跨 job 末态/起态；结构校验不能代替叙事检查。
镜头需要场景图附件时，按四向板的方位映射裁出对应单视图并登记来源；不要直接把整张四格板当成视频画面参考。裁切后分辨率不足或结构不一致时，停在资产修订阶段，不以提示词承诺画面会自动修正。

只从已经通过导演谱检查的中性镜头单生成 H3 提示词。导演谱缺任一时间段、出场顺序、站位、微表情、对白演绎或摄影机触发/停止点时，退回 P3，不允许靠编译器自由补写。编译前把本 job 每个绑定资产的稳定 ID、用途、控制范围和实际附件路径列入输入清单，并逐项核对提示词中的角色/场景/道具描述与资产一致。每个生成 job 为4–15秒，整条提示词时间线与成片时长一致；正文开头写明本 job 交付线画幅（`16:9横屏` 或 `9:16竖屏`）。最终提示词字段名和固定语法遵循官方格式；正文默认中文，也可按用户要求使用英文，冻结对白、歌词和画面内文字保持原文。先选择 `T2VA / I2VA / L2VA / FL2VA / Ref2VA`，选择依据是本次真实输入和目标状态，不是“所有任务默认全参考”。逐模式规则及官方映射见 `references/h3-prompt-compiler.md` 与 `references/official-h3-conformance.md`；只读取 H3 自有规则，不读取 Seedance 参考。

一个 H3 job 只使用一种模式和一份 capability 记录。`T2VA`不虚构素材；首/尾/全参考模式只有实际素材与当前服务 schema 支持时才使用。角色/场景/道具图作为多模态参考时使用 Ref2VA 的真实附件和标签；首尾帧模式中只绑定实际首帧/尾帧图，其他资产须已体现在该锚帧中，不得再把参考图混入帧锚模式。续镜时先检查前一条已审核并归档的视频及末态；需要画面级衔接时，从该归档视频按目标时间码抽取真实帧，作为独立图像资产登记来源视频、来源 job、时间码、用途、画幅和审核状态。按目标选择 I2VA（首帧）、L2VA（尾帧）或 FL2VA（首尾帧），在专用 `first_frame` / `last_frame` 输入中绑定帧文件，并使用官方对应指令行。抽帧是本地素材处理，不代表用户授权新的视频生成。首尾帧锚定模式和 Ref2VA 互斥，禁止把角色参考附件与首尾帧同时提交；若同时需要角色/场景参照与续接锚帧，优先将已确认视觉信息体现在锚帧内，或先采用 Ref2VA 并将续接画面作为普通参考图，不能伪称首尾帧约束。当前 provider 若提供官方 H3 Context-IR 预处理能力，先核实并按其真实 schema 调用；否则使用导演谱做本地多模态关系与时间线预检，不宣称等同官方 Context-IR。H3 原生提示词按其字段顺序编译：普通模式三字段；Ref2VA 六字段。正文使用内容主语言，中文项目可用中文描述；对白、歌词和画面真实文字保留原文。说话人 ID 稳定，`<d>`只含语言标签与逐字原句；场景切换标记只用于跨切连续说话，`<cutoff>`只表示真实截断。不得把提示词字段直接当 JSON/API 请求体。

### P5 调用、修复与状态账

完整项目使用 `project.json` 记录模型、镜头、语言单元、素材和生成任务。新项目使用 schema `1.2`，在1.1导演谱基础上要求每个beat记录观察视点和切镜理由，并给每位可见人物记录画面高度占比；schema `1.0/1.1`可读取旧草稿，进入提交前必须迁移到1.2。执行前先运行：

```powershell
python -m core.lib.lock --project path\to\project.json --channel <id> --baseline models\h3.baseline.json --out path\to\effective-capability.lock.json
python scripts/validate_project.py path\to\project.json --lock path\to\effective-capability.lock.json
python -m unittest discover -s scripts -p "test_*.py"
```

`stage=draft`可以用于文字预制作，但 job 成片时长仍须在4–15秒。Ref2VA按官方素材数量和时长上限预检；当前provider或接口限制更严时从严执行。`stage=submit`除 capability、真实素材、服务字段、用户授权和预算外，还必须通过 schema 1.2 的导演谱校验；缺少连续 beats、出场顺序、站位、人景比例、观察视点、切镜理由、运镜计划、表演计划或对白声音谱时不得提交。授权或接入能力未知时停在草稿。预算前估算任务数/重试数，达到授权上限即停止。资产图提交也逐张处理，按 `references/sequential-asset-generation.md` 执行单张费用门、用户确认门和无轮询/无自动重试约束；视频 job 的生成授权不自动扩大到资产图或反之。

每个镜头按 `planned → assets-ready → submitted → generated → reviewed` 记录状态及路径/任务ID。失败只定位该镜号、时间码和失败类型，优先修输入或提示词的最小范围；保留原版本与审核记录，不重复提交已成功镜头。不要用自动关键词或脚本结果代替人工观看。

### P6 剪辑、声音与交付

按已审镜头清单组装；音乐、环境声、动作声、画内声、OS/VO与字幕轨分开计划。按真实音轨核对白字、停顿、口型、响度、角色音色连续性和跨镜衔接。需要输出成片时核对实际画幅等于该交付线（16:9 或 9:16）、分辨率、帧率、时长、音轨、字幕和缺失镜头；技术检测与内容审阅分开登记。交付项目文件、可用素材、提示词版本、审核报告、未完成项和版本差异；没有实际媒体不称“成片完成”。完整质量门见 `references/quality-and-release.md`。
