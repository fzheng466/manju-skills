# 质量门、审片与交付

质量门用于阻止错误进入下游，不是额外审批链。按用户当前范围完成所需门；局部任务不必伪造整季交付材料。

## 阶段门

| 门 | 通过条件 | 不通过时的动作 |
|---|---|---|
| G0 范围与来源 | 模型锁定、16:9、目标交付与来源材料清楚；事实/推断/补全/未知已区分 | 补齐会改变制作路线的缺项；不把未知写成事实 |
| G0a 生成授权 | provider提交的job ID与用户授权集合完全一致，且记录授权证据和预算上限 | 保持draft；列出需要授权的job与预计费用，不自行代填授权 |
| G1 故事冻结 | 按 `script-review.md` 审查并复查修订处；P0已解决，P1有处置记录，关键选择/信息揭露/伏笔有落点；完整单集累计90–180秒，台词原句有稳定 ID | 最小化修订并维护覆盖表与跨集台账；无法判断原意时提问 |
| G2 资产可用 | 关键人物/场景/道具已有可定位的实际资产，或明确标记待补；跨机位场景四向图的结构与锚点已逐格核对 | 未核对的方向标为未知，不在提示词中声称已锁定 |
| G3 分镜可执行 | 时间线完整；每场焦点拥有者、每镜视点/景别/人物画面占比、切镜理由与状态变化明确；景别有因果变化而非全场固定中景；环境动态有来源并跨镜继承；空间/动作/声音可追踪 | 修正涉及镜头和直接相邻镜头；必要时做文字调度或按需预演 |
| G3a 故事板预演（按需） | 仅当文字镜头表无法核清剧情顺序且预演有明确收益时采用；玄幻仙侠武打不使用多格故事板；若采用则每张不超过24格，并核对时间、动作、空间接缝和参考资产 | 未采用时继续依据导演谱检查；采用后修订未通过的板和接缝 |
| G4 H3 编译可校验 | 选定模式和字段集匹配；标签定义与引用有效；台词、声音层、时码及画幅符合对应profile | 留在草稿并修复；不转成另一模型语法 |
| G5 生成记录完整 | 真实任务ID、输入文件、参数快照、结果路径和版本关联到job | 状态停留在submitted或failed，不虚报生成成功 |
| G6 内容审片 | 逐镜观看实际媒体，按时间码记录身份、空间、动作、对白/口型、声音、特效问题 | 只返修失败镜头与受影响邻镜；保留旧版本 |
| G6a 角色音色连续性 | 将各 job 的实际对白音轨按角色和 `voice_profile_id` 汇集；比较中性基准句及情绪变化，记录身份层声线漂移与剧情允许的表演差异 | 按 [角色音色档案与跨段一致性](voice-profile-and-continuity.md) 定位并返修受影响对白/音轨；没有实际音频时标记未验证 |
| G7 技术验收 | 实测文件画幅16:9；核对分辨率、帧率、时长、音轨、字幕、端点和编码 | 报告实测值与失败项；不以计划参数代替文件检测 |
| G8 交付状态 | 交付物、版本、审核状态、未完成项、已知限制、来源和复现线索清楚 | 以草稿/部分完成标示，不能称最终成片 |

## 逐镜审片表

剧本诊断和分镜审阅采用证据闭环：标明具体场次/镜头/原句或前后状态，解释它造成的观众理解问题或制作风险，再给最小修订建议。用户只要求诊断时不直接改稿；用户要求修订时保留原稿版本，并说明已修改范围。审阅同时记录成立的关键段落及其作用，不为凑问题数量拆解有效内容。对白审阅要区分角色意图、实际措辞和听者可观察回应；因果审阅检查后续行动是否由前一结果触发；时长审阅说明哪些内容并行、哪些必须先后发生。未经授权不改变定稿剧情、原句和结局。

每项缺陷记录 `shot_id / media_path / timecode / category / expected / observed / severity / fix_scope / reviewer / reviewed_at / disposition`。建议严重度：

- **阻断**：错误身份或服装、关键剧情动作不可读、致命轴线/方位错误、对白丢失/被改写、比例错误、素材损坏或侵权/授权状态未知且用户要求发布。
- **主要**：空间跳变、动作受力不成立、关键表演不清、口型与声音明显错位、连续性物件漂移、特效遮住剧情信息、环境动态凭空出现/消失、无缘由切镜使观众失去本场观察焦点。
- **次要**：局部材质/光影波动、非关键细节漂移、可在剪辑/调色/混音解决的小问题。

标签不是自动裁决。最终交付必须人工播放实际媒体；脚本只能验证结构、文件存在与部分技术值，不能判断演技、内容质量或“看起来一致”。

人工审片加问：非持有者在场时私有特效是否已收起；侧身/过肩特效是否挡身体或对话对象；同一 voice_profile_id 是否换声；台词逐字是否 ASR/人工核对（否则标未验收）；场景是否只用单格参考；道具状态是否与 ledger 一致。

## 连续性复验

角色/服装/道具状态更改后，查询使用该资产的所有镜头；场景结构和光源变化后，复验同一空间家族的构图及时间段；台词或声音修改后，复验前后停顿、口型、字幕和音乐切点。只复验直接受影响项目及相邻接缝，但记录搜索范围与结论。

任何已通过的镜头在复用或重新剪辑时都要检查新的前后关系。资产板只锁角色外观，不代表某镜头的姿势、景别或构图；审片按当前镜头意图对照，不把设计板误当视频关键帧。

## 交付清单

按用户要求选交付项，并在清单中标记 `done / pending / not_applicable`：冻结剧本和覆盖表；视觉圣经和资产账本；角色/场景/道具提示词与真实图像路径；分镜/声音/字幕表；H3模式和提示词版本；能力核验证据；提交与生成ID；生成媒体及审核表；剪辑/混音/字幕计划；最终成片实测规格；未解决问题、预算使用、修订历史和发布状态。

## 状态词汇

`planned` 仅为计划；`assets-ready` 表示输入文件已实际检查；`submitted` 表示服务确已接受请求；`generated` 表示结果文件已落地；`reviewed` 表示人员看过实际结果并留下审核记录。`approved`仅适用于明确通过的资产/镜头；`released`仅在发布动作确实完成后使用。机器校验通过不自动推进这些状态。
