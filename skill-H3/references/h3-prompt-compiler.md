# MiniMax H3 提示词编译器

## 测试提示词与测试视频路径

测试视频、H3提示词试编、模式试验、参考绑定试验和测试抽帧统一写入 `E:\Test-data-Skill\<project_id>\<batch_id>\`：提示词放 `01_prompt-tests` 或 `03_video-tests\prompts`，请求记录放 `03_video-tests\requests`，测试视频/音频/抽帧放 `03_video-tests\outputs`，审片记录放 `03_video-tests\reviews`。不得把测试 job、测试提示词、测试请求或测试媒体写入项目的 `04_h3_prompts`、`05_media`、`07_qa` 或仓库目录；这些项目目录只保存正式生产文件。

仅用于本技能锁定的 MiniMax H3。字段与语法按截至2026-10-08审阅的服务文档和示例整理；实际提交前仍须重新核对当前 H3 文档、服务入口、model/checkpoint、请求 schema 和能力限制。此文件的模式名不等于五个独立模型，也不定义服务端 JSON body。

## 1. 模式路由与字段集

选择输入形态对应的模式；同一 job 固定一种模式、一个 H3 checkpoint 和一份能力记录：

| 模式 | 输入意图 | 正文结构 |
|---|---|---|
| `T2VA` | 纯文本生成，无参考画面 | 三字段 |
| `I2VA` | 一张首帧图 | 首帧指令行 + 三字段 |
| `L2VA` | 一张尾帧图 | 尾帧指令行 + 三字段 |
| `FL2VA` | 首帧与尾帧两张图 | 首尾帧指令行 + 三字段 |
| `Ref2VA` | 多模态参考输入 | 六段式；无首尾帧指令行 |

模式到 checkpoint 的映射，以当前官方/服务文档为准；现有适配资料将 T2VA/I2VA/L2VA/FL2VA 对应到 `H3-Base-FL2VA`，将 Ref2VA 对应到 `H3-Base-Ref2VA`。不得据此猜测接入端的 API `model` 或 `task` 字段。

**三字段及顺序固定**：

1. `integrated_multimodal_description`
2. `overall_soundscape`
3. `non_diegetic_music`

**Ref2VA 六字段及顺序固定**：

1. `subject_definitions`
2. `summary`
3. `retention_analysis`
4. `detailed_description`
5. `overall_soundscape`
6. `non_diegetic_music`

最终提示词的字段标题和固定模式语法使用官方英文格式。正文可用中文或英文撰写；本项目默认使用中文，用户或具体任务要求时使用英文。无论正文语言如何，中文对白、歌词和画面内真实文字均保留原文与标点；转换描述语言时不得改写冻结台词。

## 2. 首/尾帧指令行

仅 `I2VA / L2VA / FL2VA` 使用对应指令，并放在正文第一行，空一行后才进入字段内容。以下英文格式是源资料中的格式参考，逐项核对当前文档后再用于提交：

```text
I2VA:  For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.

FL2VA: How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot N) aligns with the S.SS-second mark of the target video.

L2VA:  How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the S.SS-second mark of the target video.
```

`N`必须对应真实末镜序号，`S.SS`是该 job 的有效时长，保留两位小数。I2VA 的图只锚定开端，L2VA 的图只锚定收势；FL2VA 两张必须分别对应首末状态。正文与实际请求附件清单分开，提示词提到的图必须真实存在且映射正确。

若锚帧来自已归档视频，先把实际抽取的图像登记为独立16:9资产，并在项目清单记录来源视频资产ID、已审核来源job ID和源视频时间码。提示词的指令行、`inputs.role`和图像资产的`frame_role`必须一致。逐镜资产绑定在`asset_bindings`中列出稳定ID与用途；Ref2VA绑定映射到`<Picture N>`等真实附件，锚帧模式将帧图本身登记为`frame_anchor`，并将画面中需要保持的角色/场景/道具记为`represented_in_frame`，核对其ID已列在帧图`represents_asset_ids`中。不要在首尾帧模式添加角色板、场景板或道具板附件；首尾帧锚定和Ref2VA素材引用是互斥的H3输入模式。

使用 CompShare H3 调用 Skill 时，项目 `first_frame` 映射到 CLI `--first-frame`，`last_frame` 映射到 `--last-frame`；Ref2VA 图片参考走 `--reference-images`，视频/音频参考走各自参数。提交前先核对调用 Skill 当前版本的参数与API文档，不因 CLI 参数名称推测底层 JSON 字段或其他 provider 的写法。

续镜抽帧登记示例（路径为相对`project.json`的项目路径）：

```json
{
  "asset_id": "FRAME_JOB002_FIRST",
  "kind": "image",
  "status": "approved",
  "aspect_ratio": "16:9",
  "path": "05_media/images/job-001-end-frame.png",
  "purpose": "续接前一条已审核视频的结尾构图",
  "does_not_control": "新job后续动作与摄影机运动",
  "frame_role": "first_frame",
  "frame_source": {
    "video_asset_id": "VIDEO_JOB001",
    "source_job_id": "JOB001",
    "time_seconds": 9.96
  },
  "represents_asset_ids": ["CHAR_MAIN", "SCENE_HALL", "PROP_SEAL"]
}
```

新job的 `inputs` 将该图登记为 `{ "asset_id": "FRAME_JOB002_FIRST", "role": "first_frame" }`，模式为 `I2VA`，提示词首行依官方语法引用 `<Picture 1>`。源视频须已落盘、归档且人工审核通过；真实抽帧应落在其有效时长内。仅当新镜头需要固定结束构图时再增加尾帧并改用 `FL2VA`，不要为每次续镜机械生成两帧。

## 3. Ref2VA 六段式写法

### `subject_definitions`

先定义实际会被正文调用的参考项，使用合法 `<Subject N>`、`<Picture N>`、`<Video N>`、`<Audio N>` 标签，并明确身份/内容及控制用途。`Subject`描述会出现在成片中的人物、场景、物体、服装、风格、动作、表情或姿态；`Picture`用于具体目标帧、关键帧、剪辑锚点或分镜构图参考；`Video`用于源视频编辑/续写或整体时间结构参考；`Audio`用于实际复用或声音特征参考。编号按类别独立递增，每个标签跨全部字段含义固定，并映射到真实附件，不能用提示词编号冒充平台上传槽。提交上限按官方标准执行：图像最多9张、视频最多3段、音频最多3段，混合素材总数最多12个；参考视频及音频每段2–15秒，各类型总时长最多15秒。音频不得作为唯一输入。当前provider或接口更严时取更严值。

人物的四视图板可以作为单张图像资产映射；它用于锁身份、妆发和服装，不自动等于视频首帧。若一个参考只控制某一属性，写清用途和不控制范围，防止模型把构图图误当成角色身份图。

### `summary`

用一个短段概括目标视频和素材关系。任务类型前缀保留官方英文方括号值，例如 `[reference generation]`、`[keyframe completion]`、`[video continuation + audio reference]`；其余正文默认中文，可按用户要求使用英文。只选与素材真实用途相符的类型；普通角色、场景、动作、风格或构图参考属于 `reference generation`，不能仅因附件是视频或音频就标成编辑、续写或复用。后文说明题材、时长、主体和素材关系，不引入未定义标签。

### `retention_analysis`

逐项说明参考应如何保持或转移。画面保留值：`fully_preserved`、`partially_preserved`、`attribute_transfer`、`weak_reference`；音频保留值：`fully_copy`、`partially_copy`、`reference`、`weak_reference`。值必须按当前官方样例确认，写在对应参考上；该栏不要写说话人 `(Sx)`。

### `detailed_description`

以 `[Shot 1]` 开始，Shot 1 标签后不加时间戳。首镜给一个明确具名主体，除非空镜是有意设计，此时明确标记并说明它的叙事功能。随后按连续镜头顺序写时间线、切点、构图、位置、镜头路径、动作节拍、表演、环境变化、接续末态和可听/可见同步线索。后续 shot 的切点使用严格递增的 `At 00:03.500, the camera cuts to...` 格式，并落在目标总时长内。起始帧已有锚图时写清如何从其状态开始；不要只写“保持一致”或“电影感”。

镜头切点用当前 schema/官方示例认可的写法；本项目示例使用首镜无时间戳、后续镜头标记严格递增的项目内时间码。内部工作表可以保留秒数，但不可假定服务正文支持任何自创时间语法。

正文写可见/可听的正向结果，不在模型正文里堆“不要/禁止/不能出现”清单。把无法画出的工作流术语转换成具体动作和画面。抽象形态写成可观察形状；例如写“水滴撞在石面后分成三颗小滴”，不写“水滴如线般散开”。首镜锚定一个主体，避免并列主体和悬空“这个/那只”指代。

对白格式和保留要求见下一节。避免一个镜头塞入互相冲突的动作、景别和运镜。多人的出入场都要有画面证据或明确离场状态。

#### 从导演谱编译，而不是自由扩写

先读取镜头的 `entrance_order`、`camera_plan`、`performance_plan`、`beats` 和对白导演字段，再写 `detailed_description`。提示词按以下优先顺序保留信息：主体身份与参考绑定 → 人物可见性/出场顺序 → 空间站位与左右手 → 时间节拍与动作因果 → 微表情和听者反应 → 对白声音谱 → 运镜 → 装饰细节。接近7000字符上限时先删重复的服饰和气氛形容词，不能删站位、节拍、表演或对白控制。

逐个 beat 编译时保留中性导演谱中的人物画面高度比例、景别、主客观视点、场景前中后景锚点与切镜原因；比例参考及远景至特写的用途按 `directing-and-continuity.md`。跨景别切换必须由可见动作、视线、信息揭示或关系变化触发，写明切前焦点、切后焦点和空间轴线承接。不得把多 beat 的不同景别压成连续中景，也不得为增加所谓电影感而添无因果特写。若所选 H3 模式不能表达硬切，改用服务支持的分段/镜头表达或后期剪辑，不得将镜头切换写成该模式未支持的字段。

每个 shot 的正文按可执行顺序展开：

1. **首态锁定**：时间窗、在画面内的人、完整遮挡/画外的人、场景锚点、人物画面区域、身体朝向、视线、持物手与道具状态。
2. **摄影机锁定**：起始机位、景别、轴线侧、主体与焦点；若移动，只写当前 beat 的一个主运动及停止条件。
3. **动作节拍**：按 `beats` 的连续时间窗逐段写主动作、路径、接触、反应和结束状态；同一人物不能在一个时间窗同时完成互斥动作。
4. **揭示顺序**：需要后出场的人在揭示时间前保持完整遮挡或画外；写清触发、首次可见部位、到达位置和识别停留。
5. **表演过程**：先写触发前基线，再写两到三个按顺序发生的面部/呼吸/身体信号，最后写压回或停留状态；说话者和听者分开。
6. **对白声音谱**：在 `<d>` 外写开口前动作、起止时间、音量、音色、语速、情绪策略、合法停顿、关键词重音、句尾收声、闭口后的反应；`<d>` 内仍只放冻结原句。
7. **切点与末态**：切镜只发生在明确时间点和动作/视线/声音依据上；每次切后重新定义机位。结尾写人物、表情、左右手、道具、镜头和持续声音的具体状态。

推荐使用紧凑时间句，例如“0.00–1.60秒……；1.60–3.20秒……”，但时间句必须来自导演谱，不能为了显得精确而虚构。不同 beat 的时间严格递增并覆盖完整 job。不要在一段里同时写“缓慢推近、俯摇、切手部特写、抬到眼部近景”；它们必须成为顺序明确的 beat 或拆成独立 shot/job。

首次相遇、伏击和身份揭示必须在正文中出现明确的可见性句。示例：`0.00–3.80秒，画面中只有角色A；角色B完整位于西柱后，脸、手和衣角均不进入构图。` 若提示词只写“柱后留一段深影”，模型可能提前生成人物，不能通过出场顺序检查。

### `overall_soundscape` 与 `non_diegetic_music`

最终提示词的 `overall_soundscape` 用1–4句中文或英文写全片环境声、动作声和非语言人声，不复述对白、歌唱或画内音乐；`non_diegetic_music` 用1–3句中文或英文描述观众可听的配乐，以乐器、速度、节奏和动态变化为主。按项目选定的提示词语言保持一致。只有用户明确要求全片绝对静音时才使用 `N/A`。不要把已经生成或后期完成的音轨说成提示词中“确保”的结果。

## 4. 对白、OS/VO 与说话人

角色基础声线由稳定的 `voice_profile_id` 控制；完整档案与跨段审听规则见 [角色音色档案与跨段一致性](voice-profile-and-continuity.md)。同一角色跨 job 必须复用同一基础声线锚点，不能只依赖每句临时写“温柔/低沉”等情绪词。局部 `(Sx)` 标签仍按本节在每个 job 内编号，并在项目记录中映射到稳定 `speaker_id` 与 `voice_profile_id`。

`(Sx)`在一个 job 内按实际发声先后从 `(S1)` 编号；同一 job 重复出现同一说话人沿用同一编号。没有发声的角色不占编号。跨 job 重新开始本段编号，`speaker_id`与项目台词 ID 的映射保存在外部项目表。

在该角色本 job 首次发声处写稳定身份层声线锚点，随后再写本句语气、音色变化、语速等表演层信息；同 job 后续句沿用该锚点，跨 job 重新写精简版本。`<d>`内部只放语言标记和冻结的原句，含标点、重复、停顿字样均不得擅改。例如：

```text
角色基础声线：中低音区、温润厚实、气息稳定、普通话咬字清楚，句尾自然收住。本句因压迫对手而音高重心略降、语速放慢，主音色与口音保持不变。她平稳地说：沈砚 (S1)，<d>[Chinese] 此处填写冻结剧本中的原句。</d>
```

上例是格式示意，不能当成具体项目台词。格式标签的空格、括号、语言名称须以当前 H3 示例为准。语气文字在 `<d>` 外，不混进画面动作段。分散到多个镜头的 utterance 片段按时间顺序拼接，与冻结原句逐字比较。

“冷冷地说”“压低但坚定”不足以作为正式对白控制。正式编译至少包含：开口前呼吸/视线动作、明确起止时间、音量、音色、语速、情绪力度、一个表达策略、允许停顿的位置与长度、最多两个关键词重音、句尾走势、闭口后的说话者反应、听者在具体词或句尾后的反应。停顿和重音说明全部放在 `<d>` 外，不能在冻结原句中插入省略号、斜线或括号。

画内对白期间，除自然口型、呼吸和低幅眉眼变化外，默认保持脚位、身体朝向、主要手势和摄影机稳定。若对白必须伴随动作，动作只保留一个简单连续行为，并说明它不遮挡嘴部和眼睛。对白开始前和结束后分别留出可读时间；听者不得在尚未听到触发词时提前变脸。

OS/VO需明确是画外发声，若人物在画面内，应按当前官方格式说明嘴部静止；本技能的 H3 适配说明建议使用“嘴唇始终完全闭合”的可见证据。不能把 Seedance 的口型控制符迁入 H3。画内文字用模型可识别的直接引文描述其实际内容，不把字幕当对白。

## 5. 素材分配与额度

官方仓库标准记录 Ref2VA 图像最多9张、视频最多3段（单段2–15秒、合计最多15秒）、音频最多3段（单段2–15秒、合计最多15秒，必须与图像或视频同用）、混合文件最多12个。它们是模型上限；提交前还要核验provider当前接口，若接口更严则从严执行，若接口宣称更宽也不能超过模型上限。来源与核验版本见 `official-h3-conformance.md`。

若当前上限确认，素材取舍次序按镜头风险决定：具体首/尾/构图帧锚、主要角色板、关键场景结构、关键道具、动作/音色参考。超限先删掉“定义但正文未引用”或低贡献参考，将稳定外观改用准确文字，不擅自压缩或拼接造成歧义。音频不能单独提交等规则也必须按当前接口重新核验。

## 6. Profile 参数与运行时核验

官方模型的每个生成 job/成片时长必须为4–15秒，提示词时间线必须与 job 总时长相符；provider若规定更严范围则取交集。job 内部的 `[Shot N]` 是剪辑段，可以短于4秒，但每个切点必须位于总时长内。官方支持多种比例；本技能项目额外固定16:9。官方基线为24 FPS、32 kHz立体声、默认短边768。提交前仍须核验provider对本次模式的实际支持；若服务以 `auto/adaptive`处理参考帧，只有最终输出及所有控制帧均为16:9才可提交，否则阻断。

图像/视频/音频路径、`ratio`、seed、分辨率、duration、`task`、model、endpoint等属于服务请求外壳，不得从此文件示例臆造。不要将任何提示词字段名直接复制成接口JSON键。记录实际能力证据的来源、核验日期、provider、精确 model ID/checkpoint、接受的比例、模式、时长和素材限制。无法核实时保留草稿。

## 7. 投喂前人工检查

- 模式、字段集、指令行及附件真实一致；Ref2VA不加首尾帧指令行。
- job时长与当前profile及请求一致；默认目标画幅16:9。
- 标签先定义后引用，定义项都实际使用；附件路径可读取，内容已核图。
